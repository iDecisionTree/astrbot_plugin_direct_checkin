# 直属队打卡插件用户使用文档

> 适用平台：QQ  
> 插件命令前缀：`/d`  
> 统计时间：北京时间  
> 机器人：西北大学计协软萌技术伙伴「词九」  

---

## 1. 这个插件是做什么的

这是词九负责的直属队学习打卡小助手喵。

普通同学需要先绑定自己的学号和姓名。之后每次把学习记录整理成 `.docx` Word 文档发到 QQ，再引用这份文档发送 `/d`，插件会保存材料、检查是否重复、进行 AI 审查，并告诉你这次是否有效、是否计入本周次数。

每个考核周需要完成 2 次有效打卡。统计周期为北京时间周一 00:00 到周日 23:59。同一天可以完成两次，只要两次确实是不同学习任务，或者同一任务有实质性的新进展。

## 2. 第一次使用：绑定身份

第一次使用请发送：

```text
/d <学号> <名字>
```

例如：

```text
/d 2026123456 张三
```

绑定成功后，以后不需要重复绑定。

注意：

- 一个 QQ 只能绑定一个学号。
- 一个学号只能绑定一个 QQ。
- 如果学号或 QQ 绑定错了，请联系管理员处理，不要尝试用另一个身份覆盖。
- 插件认的是 QQ 用户 ID，不认群昵称。

## 3. 怎么打卡

### 3.1 正确步骤

1. 把本次学习记录整理成 `.docx` Word 文档。
2. 在 QQ 中发送这份 Word。
3. **引用刚才那份 Word 消息**。
4. 在引用状态下发送：

```text
/d
```

词九会开始检查并处理这次打卡。

### 3.2 为什么必须引用文件

必须引用，是为了明确告诉插件“这一次打卡对应哪一份文件”。

插件不会自动猜“你最近发的文件”，这样可以避免群聊里串文件、认错材料。

### 3.3 支持什么 Word

首版支持：

```text
.docx
```

旧版 `.doc` 请先用 Word/WPS 另存为 `.docx` 再提交。

## 4. 一份有效打卡应该写什么

不要求固定模板，也不要求固定字数，但建议至少能看出三件事：

### 4.1 学习内容

这次具体学了、做了什么。

例如：

```text
学习了 FastAPI 的依赖注入，并把登录鉴权改成统一依赖。
```

### 4.2 实践过程

你实际做了哪些操作、实现、实验、验证、测试或调试。

例如：

```text
把原来三个接口里重复的 Token 校验提取出来，补了未登录和过期 Token 两种测试。
```

### 4.3 学习收获

你掌握了什么、遇到了什么问题，或者下一步打算怎么改。

例如：

```text
理解了依赖可以继续嵌套。下一步准备把权限校验也拆成依赖，并补异常处理。
```

## 5. 哪些内容可以打卡

内容不限编程语言、技术栈和项目主题，只要与软件开发或相关技术能力提升有关即可。

常见内容包括：

- 学习新编程语言或语言新特性；
- 学习框架、算法、数据库、工具链；
- 学习开发工具、设计软件或相关软件；
- 调试、测试、性能优化；
- 给自己的项目增加功能；
- 修复 Bug；
- 对同一个项目持续迭代。

持续做同一个项目完全没问题。关键是这一次要能看出相较之前有新的、实际的进展。

## 6. 哪些情况一般不会通过

下面这些情况通常不会算有效打卡：

- 只有教程链接，没有自己的学习和实践记录；
- 大段复制教程、文章或他人内容，没有自己的实践；
- 和自己以前提交的材料实质上一样；
- 只把同一个成果拆成两份来凑次数；
- 内容与自己的实际学习无关；
- 文档几乎是空的，无法判断做了什么。

可以使用 AI 帮你整理学习记录，但最后请自己核对，确保写的是你真实完成的内容。

## 7. 每周次数怎么算

每个考核周需要：

```text
2 次有效打卡
```

周统计范围：

```text
北京时间 周一 00:00 ～ 周日 23:59
```

### 7.1 同一天能不能打两次

可以。

但两次必须分别体现：

- 不同学习任务；或
- 同一任务的实质性新进展。

重复同一成果不能算两次。

### 7.2 一周能不能交超过两次

可以提交。

如果本周已经有 2 次计分打卡，后续材料仍会保存和审查。内容有效的话，会记为“有效额外材料”，但不会让本周从 2 次变成 3 次，也不能拿去补其他周的缺卡。

## 8. 插件会怎么审查

你发出 `/d` 后，词九会依次做这些事情：

1. 确认你的 QQ 已绑定学号。
2. 确认当前没有暂停打卡。
3. 读取你引用的 `.docx`。
4. 保存原文件。
5. 检查是不是和之前提交的内容重复。
6. 查看本周已经计了几次。
7. 用 AI 判断这次是否有实质性的学习/实践进展。
8. 告诉你是否有效、是否计次，以及一条简短评价。

AI 审查会稍微宽松一些，不会因为排版普通、文字不长、没有固定标题就直接判失败。

## 9. 常见回复是什么意思

### 9.1 “打卡成功，本周 1/2”

说明：

- 文档有效；
- 没有命中重复；
- AI 审查通过；
- 这次已经计入本周。

### 9.2 “本周已经 2/2，这次保存作额外材料”

说明内容本身有效，但本周计分次数已经满了。

材料仍会保存，可作为学习质量记录，但不会再加一次。

### 9.3 “这份和之前提交一致”

说明命中了重复检测，本次不会计次。

如果你做的是同一个项目，请把本次新增功能、修复、测试、实验结果等新进展明确写出来再提交。

### 9.4 “实践过程有点少”

说明 AI 没看出足够的实际操作或进展。

可以补充：

- 你具体改了什么；
- 做了什么实验；
- 怎么验证；
- 遇到什么问题；
- 修复前后有什么差异。

### 9.5 “审查服务开小差了”

说明文件已经保存，但 AI 审查出现技术错误，因此暂时没有计次。

稍后可以再次引用**同一份原文件**发送 `/d` 重试。这种技术失败不会因为文件相同而把你的重试直接当重复。

## 10. 普通用户帮助

发送：

```text
/d help
```

词九只会返回普通同学可以使用的命令，不会把管理员指令混进来。

普通命令：

```text
/d <学号> <名字>    首次绑定
/d                  引用 .docx 后打卡
/d help             查看普通帮助
```

管理员命令不会出现在普通帮助中。

## 11. 暂停打卡

遇到考试周、节假日或其他统一安排时，管理员可以暂停打卡。

暂停期间你发送 `/d`，插件会告诉你暂停范围和原因。

### 11.1 当天暂停

当天不接收新打卡，第二天自动恢复。

因为制度没有每日必须打卡要求，所以当天暂停并不改变“本周总共 2 次”的要求。

### 11.2 本周暂停

整周会被标记为暂停周，本周不按缺卡处理。

管理员如果中途恢复接收，本周默认仍保留暂停周豁免，避免临时恢复后追溯要求大家补两次。

## 12. 管理员使用说明

以下命令只有插件管理员可以使用。

初始管理员 QQ：

```text
274734439
```

### 12.1 查看完整帮助

```text
/d admin help
```

返回普通命令 + 全部管理员命令。

### 12.2 添加管理员

```text
/d admin add <QQ>
```

例如：

```text
/d admin add 123456789
```

### 12.3 移除管理员

```text
/d admin remove <QQ>
```

系统至少会保留 1 名管理员，所以不能删除最后一名管理员。

### 12.4 人工增加一次当前周打卡次数

```text
/d add <学号/QQ>
```

用途：统计纠错、特殊情况人工补记。

这条命令只添加“当前北京时间周”的人工计次，不会伪造 Word 文档，也不会修改原来的 AI 审核记录。

### 12.5 人工减少一次当前周打卡次数

```text
/d remove <学号/QQ>
```

用于撤销一次人工计次或修正统计。

不会删除同学已经提交的 Word。

### 12.6 暂停当天

```text
/d skip d <可选原因>
```

例如：

```text
/d skip d 系统维护
```

从执行时开始暂停到北京时间当天结束。

### 12.7 暂停本周

```text
/d skip w <可选原因>
```

例如：

```text
/d skip w 期中考试周
```

当前周标记为暂停周，本周不计缺卡。

### 12.8 恢复

```text
/d resume
```

立即恢复接收打卡。

如果之前是整周暂停，本周默认仍保留“暂停周”豁免，只恢复提交入口。

## 13. 管理员导出 Excel

### 13.1 导出全部同学

```text
/d get
```

词九会返回一个 Excel 文件。

### 13.2 导出某一位同学

```text
/d get <学号/QQ>
```

例如：

```text
/d get 2026123456
```

或：

```text
/d get 123456789
```

### 13.3 Excel 里有什么

默认包含：

- 用户汇总；
- 每次打卡明细；
- 人工加减次数记录；
- 暂停记录。

打卡明细中会有 AI 简评、是否计次、重复检测结果和文件归档路径，但不会把 Word 正文整篇复制进 Excel。

## 14. 管理员统计

发送：

```text
/d stat
```

默认统计当前北京时间周。

普通周会按：

```text
0 次
1 次
2 次及以上
```

分类，并返回人数汇总和饼图。

例如：

```text
词九统计好啦～本周共 32 人：已完成 21 人，1 次 7 人，0 次 4 人。
```

统计图不会出现姓名、学号或 QQ。

## 15. 文件保存位置

所有打卡 Word 会统一保存到：

```text
/mnt/nas/direct_checkin/<学号>/
```

词九只会操作 `/mnt/nas/direct_checkin/` 这个打卡目录，不会去读取 NAS 里的其他目录。

文件会使用时间 + 唯一编号重新命名，避免同名覆盖。

## 16. 和词九交互时会看到什么

这个插件不会用冷冰冰的系统提示和你说话。正常情况下，你会一直看到「词九」的语气：软一点、短一点，但规则和结果会说清楚。

例如：

```text
绑定好啦，同学～词九记住你啦。以后引用 .docx 后发 /d 就能打卡喵。
```

```text
打卡成功～本周 1/2。词九看过啦：这次实现和测试过程都比较清楚，有实质性进展呀。
```

```text
这次先不计次呀。词九看到的问题是：实际实践过程太少。补清楚你做了什么、怎么验证，再来一次就好。
```

遇到数据库、文件保存、权限等技术问题时，词九会少卖萌一些，优先把问题和数据状态说明白，不会拿可爱语气糊弄错误。

## 17. 隐私说明

- 普通同学不能查询其他人的打卡记录。
- 只有插件管理员可以导出全体统计和明细。
- 插件不会用群昵称识别身份，统一以 QQ 用户 ID 为准。
- Word 正文不会整篇写进日志。
- AI 审查时会尽量只提供完成审核所需的技术内容，不主动发送 QQ 号等无关个人信息。
- 插件不会执行 Word 里的代码、宏或指令。

## 18. 打卡写作小建议

不需要写得很长，写清楚比堆字数更重要。

一个简单好用的结构：

```text
今天做了什么：
给自己的后端项目加了文件上传接口。

怎么做的：
用 FastAPI UploadFile 接收文件，限制了扩展名和大小，并补了空文件和超限测试。

结果/问题/下一步：
目前本地测试能正常上传。发现同名文件会覆盖，下一步准备改成 UUID 文件名并补清理逻辑。
```

这种记录不长，但能看出明确的学习内容、实践过程和下一步，通常比大段复制教程更有效。

## 19. 常见问题

### Q：我一天能打两次吗？

可以，只要两次不是同一个成果重复提交。

### Q：我一直做同一个项目，会不会被判重复？

不会仅因为项目相同就判重复。把本次新增功能、Bug 修复、测试结果或其他新进展写清楚即可。

### Q：我用了 AI 写代码或整理文档，还能打卡吗？

可以。关键是记录要反映你真实完成的学习和实践，并且你自己核对过内容。

### Q：为什么超过两次还要审查？

因为制度允许多提交的有效记录作为学习质量材料，只是每周最多计两次。

### Q：为什么不能直接发 Word 后立刻 `/d`，必须引用？

群聊中可能同时有很多文件。引用可以保证插件不会认错材料。

### Q：文件已经保存，但没计次怎么办？

先看机器人给出的原因。如果是 AI 技术故障，可以稍后引用原文件重试；如果是内容不足或重复，请补充新进展后再提交。

### Q：绑定错学号了怎么办？

联系插件管理员处理。普通用户不能自己覆盖绑定，避免身份冲突。

## 20. 命令速查

普通用户：

```text
/d <学号> <名字>        绑定
/d                      引用 .docx 打卡
/d help                 普通帮助
```

管理员：

```text
/d admin add <QQ>       添加管理员
/d admin remove <QQ>    移除管理员
/d admin help           完整帮助
/d add <学号/QQ>        当前周人工 +1
/d remove <学号/QQ>     当前周人工 -1
/d skip d [原因]        暂停当天
/d skip w [原因]        暂停本周
/d resume               恢复接收
/d get [学号/QQ]        导出 Excel
/d stat                 当前周统计
```

---

如果词九提示的是权限、文件解析、重复检测或 AI 审查问题，按提示处理就好，不用反复刷同一条命令呀。
