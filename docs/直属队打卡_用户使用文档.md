# 直属队打卡插件使用说明（v1.1）

词九负责保存学习记录、审核内容和统计每周进度。默认按北京时间自然周考核，每周目标为 2 次；实际目标以 `/d help` 和统计卡片为准。

## 绑定与打卡

先发 `/d 学号 姓名`，例如 `/d 2026123456 张三`。一个 QQ 对应一个学号，不能自行覆盖已有绑定。群昵称不影响身份识别。

之后按以下步骤提交：

1. 把学习过程整理成 `.docx` Word 文档，上传到 QQ。
2. 引用这条文件消息，发送 `/d`。
3. 等待词九回复，按回复确认是计次成功、额外材料还是需要补充。

旧版 `.doc`、损坏文档、超限文件不接受。默认文件上限为 20 MiB，可由管理员配置。只有图片而没有可判断正文的材料可能无法通过；当前不做图片内容审核。

不要求固定字数或模板。建议写清楚：学了什么、实现或解决了什么、如何测试验证、得到什么结果或下一步打算。同一项目可以持续提交，请突出新增功能、修复、实验或结论。

## 次数怎样计算

默认自然周为周一 00:00 至下周一 00:00（不含结束时间）。一次请求的日期、周次和文件归档标签均按接收时刻确定，即使审核跨过午夜也不会跳到另一周。

- **自动打卡同一天最多计一次**，审核通过的其他提交保存为额外材料。
- 自动打卡与人工计次共享本周目标，满额后仍可提交并审核，额外材料不增加本周次数。
- 人工加次不受自动打卡的每日限制；人工减次只减少当前周净次数，不能减到零以下。
- 管理员扣减后可在满足每日限制的日期继续打卡；扣减不会把当天变成“未计过次”。
- 本周目标首次确定后冻结。修改配置从下周生效，历史周不会随配置重新计算。
- 有效额外材料不能抵扣其他周缺卡。

## 查重与回复

| 回复类型 | 意义与下一步 |
| --- | --- |
| 打卡成功，本周 `实际次数/实际目标` | 本次已计入进度，材料已保存 |
| 同日／满额的额外学习记录 | 审核通过并保留，不增加本周计次 |
| 和本人历史内容一致 | 文件或规范化正文完全重复，本次不计次 |
| 内容审核不通过 | 按词九反馈补充真实学习过程与验证结果后重新提交 |
| 审查服务异常 | 已保存材料，尚未计次；稍后引用原文件，用一条新消息重试 |
| 无法确认消息唯一标识 | 本次写操作没有执行，请管理员检查适配器 |

高相似不等于重复拒绝：词九会把相似度、本人历史相关段落和本次新增内容一起交审核器判断。跨用户重复只提供风险提示，不附其他人的身份或正文。

同一消息被平台重复推送时，只返回原结果，不重复计次。重启中断的请求会提示管理员核对；请用新消息重试，不反复转发同一个事件。

## 管理员命令

管理员按 QQ 号鉴权。QQ 群管理员身份并不自动等于插件管理员。

| 命令 | 作用 |
| --- | --- |
| `/d admin help` | 完整帮助 |
| `/d admin add <QQ>` | 添加插件管理员 |
| `/d admin remove <QQ>` | 移除管理员；超级管理员和最后一位受保护 |
| `/d add <目标>` | 当前周加一次，满额后记人工额外记录 |
| `/d remove <目标>` | 当前周扣减一次，零次时拒绝 |
| `/d skip d [原因]` | 暂停当天，次日 00:00 自动结束，不改变周目标 |
| `/d skip w [原因]` | 暂停本周并豁免本周考核 |
| `/d resume` | 恢复接收；若本周为整周暂停，则取消该周豁免 |
| `/d get` | 全员 Excel |
| `/d get <目标>` | 个人 Excel |
| `/d stat` | 本周文字统计与图片 |

目标可以是学号或 QQ；推荐 `/d add sid:2026123456`、`/d get qq:123456789`。数字同时匹配不同用户时必须明确前缀。多余命令参数会拒绝处理，暂停原因默认最多 100 字。

## 如何读统计和报表

统计卡片按在队用户分为“已完成、进行中、未开始”。达到本周目标即已完成；有次数但不足目标为进行中；零次为未开始。目标为 1 时自然没有进行中的用户。

暂停周显示豁免状态及原因，不显示完成率；未绑定任何用户时显示等待加入状态。渲染失败仍有文字统计。

Excel 共五张表：

| 工作表 | 内容 |
| --- | --- |
| 本周总览 | 本周目标、人数、完成率、分布及待完成名单；个人导出只显示本人 |
| 用户汇总 | 每人本周进度、累计计次、有效材料、人工调整、完成周与豁免周 |
| 打卡明细 | 每份材料的状态、时间、文件名、审核与查重结果 |
| 人工调整 | 加次、额外记录、扣减及操作人 |
| 暂停记录 | 暂停区间、原因、恢复时间和豁免状态；个人导出也保留这份共同考核背景 |

表格已冻结表头与身份列，支持筛选。部分分项与技术列默认折叠，可以点击列上方的分组按钮展开。QQ、学号以文本保存，前导零不会丢失。日期、数量、比例可以直接排序或统计。

几个容易混淆的指标：

- **累计周有效计次**：每周“自动计次 + 人工计次 − 扣减”限于零和该周目标之间，再把各周相加。
- **有效材料数**：审核通过的所有材料，包括同日和满额后的额外材料；人工加次没有材料，不计入这里。
- **人工计次／人工额外／扣减**：分开列示，不把人工额外记录当成完成周目标。
- **完成周数**：达到各周目标的正常周数；豁免周单列，不冒充完成周。
- **系统异常**：模型或处理技术问题，与内容／文件未通过分开统计。

例如两周目标均为 2，第一周有 4 份有效材料、计次 2，第二周计次 1，则累计周有效计次为 3，有效材料数为 5。

## 重置与恢复

`/d reset` 先展示说明。同一管理员在 120 秒内用 **两条独立消息** 发送 `/d reset confirm` 才会执行；平台重复推送第一条不会推进确认。重启后要重新确认。

重置删除所有绑定、提交、人工调整、暂停和原审计记录，并清空配置的 **NAS 专用目录内全部内容**；保留管理员和消息防重放回执。管理员必须先确认该目录专用于本插件。

执行期间进入维护状态，等待正在处理的请求结束，再暂存文件并清库：

- 清库失败：恢复归档；恢复失败则继续维护，提示待处理。
- 清库成功、文件删除失败：明确回复“数据已重置，文件清理未完成”。不能把它理解成数据库还在。
- 重启时按恢复日志继续恢复或清理。修复目录权限后，也可再次完成两次重置确认处理上次残留。

有残留时请保留 `reset-journal.json` 和 NAS 中的 `.checkin-reset-*` 暂存目录，不要手工删掉或移动。由维护人员检查日志和目录权限，再完成恢复。
