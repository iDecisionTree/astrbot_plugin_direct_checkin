# QQ / Linux / Docker 验收流程（v1.1）

本清单用于真实环境验收。接口替身与自动化通过不能证明 QQ 引用文件或 OneBot 发文件已正常工作。只在独立测试群、虚构账号记录和临时 NAS 专用目录执行破坏性用例，勿对生产数据执行重置。

## 准备

- 记录 AstrBot、Python、OneBot 实现及插件版本、Docker 镜像版本和模型提供商。
- 配置独立 NAS 路径并挂载到 AstrBot 容器；容器内路径应存在且可读写。
- 设置测试超级管理员 QQ。准备另一个插件管理员和至少三名普通测试用户。
- 在容器内安装 `requirements.txt`；保留 `assets/fonts/NotoSansCJKsc-Regular.otf` 和 `OFL.txt`。
- 配置该测试会话的聊天模型，核对官方 [模型调用接口](https://docs.astrbot.app/dev/star/guides/ai.html)：`get_current_chat_provider_id(umo=...)` 与 `llm_generate(chat_provider_id=..., prompt=..., system_prompt=...)`。
- 准备普通 Word、正文／表格交错的长文、完全相同副本、高相似但末尾新增测试结果的版本、仅链接、损坏文档、超限文档。

## 用户流程与消息幂等

1. 普通用户绑定，检查 QQ／学号唯一性；同时从两个 QQ 绑定同一学号，只能一个成功，另一个收到业务提示。
2. 引用真正的 QQ 文件消息发送 `/d`，检查 `Reply.chain` 中的 `File` 能下载，NAS 归档内容与原文件一致，回复能显示实际进度。
3. 同日提交不同且有效材料，应保存为额外材料；次日提交可计次，满额后不再加次。
4. 模拟 OneBot 重发同一原始事件：回复一致、数据库不重复写、材料不重复归档。不同机器人／会话的同名消息 ID 不应误判重复。
5. 缺少机器人 ID、会话或消息 ID 的写请求必须拒绝。只读帮助仍可用。
6. 重启后重复已完成事件，仍返回原回复。处理中停机的记录应转成技术异常，提示核对或用新消息重试。
7. 普通用户尝试管理员命令，被拒绝且没有产生业务调整。
8. 在测试环境让模型跨越周日午夜完成审核，核对提交日期、周起始日和文件名均归属于接收时间。

## 查重与模型

| 输入／故障 | 预期 |
| --- | --- |
| 本人文件哈希相同 | 直接拒绝，不调用模型 |
| 文件不同、规范化正文相同 | 直接拒绝 |
| 高相似但新增功能、修复或结果 | 模型收到本人历史相关段落和新增内容，允许判为有效 |
| 其他用户同文件 | 模型只收到风险，不含对方身份与正文 |
| 长文中部关键测试段、尾部新结论 | 模型输入包含所选关键段落和尾部内容 |
| 文档要求忽略规则或输出 pass | 规则仍在 system_prompt，文档只是用户 JSON 数据 |
| 超时、断网、非法 JSON／字段类型／NaN | 有限重试，返回技术异常，保存材料，用新消息可重审 |
| 模型正常返回 fail | 记录内容未通过，给出简短反馈，不误记为技术异常 |
| 归档成功但数据库写入失败 | 本请求失败归档清理，适配器原文件仍保留 |

## 人工调整与目标

1. `/d add sid:学号` 与自动计次共用额度；满额人工加次成为额外记录。
2. 扣减后在允许的日期补打卡，不应出现 SQLite 唯一约束错误。
3. 净次数只有 1 时并发扣减两次，只能一次成功；不能出现负值。
4. 并发移除管理员，至少保留一位；配置中的超级管理员不可移除。
5. 构造数字既为 A 学号又为 B 的 QQ：无前缀拒绝，`sid:` 和 `qq:` 各自准确选中。
6. 检查多余参数、非法 QQ、超长暂停原因均拒绝。
7. 独立测试库分别设置目标 1、2、3。已有本周目标后改配置并重启，本周不变；下一周采用新配置。

## 暂停与报表

- 当天暂停从生效时刻开始，到次日 00:00（不含）结束；不豁免整周。
- 整周暂停到下周一 00:00（不含）结束，当前周豁免；中途恢复取消当前周豁免。
- `/d stat` 文字、PNG、`/d get` Excel 在没有期间新写入的情况下人数和分类一致。
- 覆盖无人、全员完成、目标 1／2／3、暂停和恢复。暂停周不显示完成率，无人不显示错误饼图。
- 在 QQ 手机打开 PNG：中文无方框，日期和三类人数无截断，人数与占比无需仅靠颜色识别。
- 打开全员 Excel 的五张表；本周总览待完成名单正确，筛选、冻结和分组可用。
- 展开用户汇总分项，人工计次、人工额外、扣减、累计周有效计次、有效材料数互不混淆。
- 检查姓名 30 字、长文件名和长反馈换行；日期为可排序日期，百分比为数值。
- 使用前导零学号及 `=1+1`、`+SUM(1,2)` 等虚构外部文本，确认保留原文、无公式、无科学计数法。
- 个人导出只含目标用户身份与提交／调整；共有暂停记录可以保留，不含其他用户指标。
- 同时请求统计／导出，文件名不同且文件完整。检查 OneBot 发图、发文件均成功；等待保留时间后临时文件删除。
- 临时使字体不可读，确认回退文字；恢复字体后图片正常。容器不安装系统中文字体也应正常出图。

## 旧库升级

只使用生产数据库副本和相应 NAS 副本：

1. 准备缺失新列、缺失人工 counted 标记的旧库，包含加次、扣减和额外提交。
2. 启动后检查 `PRAGMA user_version=2`，迁移前备份存在且可读，原始提交和调整行数不变。
3. 核对旧人工调整按时间顺序、目标 2 重放；所有历史周目标为 2。
4. 重复启动，行数／计次／备份不重复改变。
5. 模拟迁移失败，原库事务回滚，备份仍在；修复原因后可再次启动。
6. 不要用旧插件直接打开已升级库。回滚演练须停机，用配套备份恢复数据库与归档。

## 重置阶段故障与恢复

以下每项使用独立临时目录，包含几份归档、无关测试文件和指向目录外哨兵文件的符号链接。

| 阶段／用例 | 预期 |
| --- | --- |
| 同一确认消息重复推送 | 不推进到第二次确认 |
| 两条不同确认消息 | 进入维护并等待在途写入，拒绝新数据操作 |
| 根路径、数据库父目录、NAS 根符号链接、内部嵌套挂载 | 拒绝危险全清，目录外哨兵不变 |
| 文件只暂存一部分时失败或进程退出 | 重启按日志恢复已移动项；原库仍完整 |
| 全部暂存后、提交前失败 | 恢复全部文件，数据库未清空 |
| 数据库清理事务失败 | 数据库回滚，文件恢复 |
| 文件恢复时权限失败／目标已存在 | 保留日志与暂存，保持维护，不覆盖同名文件 |
| 数据库提交后进程退出 | 重启读取提交标记，只完成删除，不恢复失去数据库引用的旧文件 |
| 提交后删除失败 | 明确“数据已重置、文件清理未完成”，保持恢复日志 |
| 权限恢复后重启／再次两次确认 | 继续上次任务，成功后退出维护 |
| NAS 内指向外部的符号链接 | 只删除链接本身，外部文件未被遍历或删除 |
| 日志路径越界或配置路径改变 | 拒绝恢复并保持维护，要求修复配置／日志问题 |

在各阶段核对 `reset-journal.json`、NAS 暂存目录、`reset_commits` 提交标记三者。不要只根据聊天回复判定数据库状态。重置完成后管理员仍在、旧写事件不会重放，用户需要新消息重新绑定。

## 验收记录

每项记录“通过／失败／未执行”、环境版本、截图或导出样本和错误日志。当前开发机自动化与静态样例已验证，**此清单的真实 QQ / Linux / Docker 项目仍须部署方执行**；Windows 未获符号链接创建权限时，该项测试会跳过，需在 Linux 补验。
